# Research-Paper Demos {#sec:paper}

DemoCreate's second domain is the research paper. A scientific result typically ships as a PDF *and* a codebase, and a good overview of it walks the reader through the title and authors, the abstract, the key figures, and the architecture of the implementation that produced them. The `paper/` subsystem treats that overview as exactly the same compilation problem as a software tour: a PDF (plus its figures and codebase) is read into a structured summary, and `build_paper_demo` composes that summary into an ordinary `Demo` value — after which the *identical* narration, synchronization, animation, and export pipeline ([@sec:architecture]) renders it. Nothing in the paper path is a special case downstream; it is content authored into the same spine. [@fig:paper_flow] shows the whole path end to end.

## Reading a Paper with Zero Pip Dependencies

The PDF path wraps poppler command-line utilities [@poppler2024], not a Python PDF library, so it adds no PDF-specific pip dependency to an otherwise installed DemoCreate environment. `paper/pdf.py` uses `pdfinfo` for metadata, `pdftotext` for text and `pdftoppm` for page PNGs. These real binaries must be usable on `PATH`; a pip extra does not supply them. Missing tools raise `BackendUnavailableError`. The source PDF is read rather than edited, while page rendering writes output images. Extracted text and rasterization depend on the input PDF and poppler build, so this is not a cross-machine byte-identity guarantee or an OCR guarantee for scanned pages.

`paper/extract.py` turns those calls into a render-ready `PaperSummary`: title and authors from `pdfinfo` metadata, the page count, and a sorted list of figure images collected from a sibling directory. Figures are *collected*, not extracted from the PDF: the subsystem takes a directory of already-exported figure PNGs (the reproducible analysis outputs the project already has), which keeps figure quality high and the implementation simple.

## Real Structure: Abstract, Captions, and Sections — Skipping the TOC

The depth of a paper demo comes from `paper/structure.py`, whose three pure extractors read the paper's *real* prose rather than generic boilerplate, and whose recurring adversary is the table of contents (TOC) that long manuscripts front-load. The extractors operate on already-extracted text, so they are fully testable without poppler; only `summarize_structure` touches the guarded poppler path.

`extract_abstract` searches standalone `Abstract` markers, rejects TOC-like candidates using dotted leaders and trailing page numbers, and prefers substantial prose (at least 200 characters). If that fails it searches for a substantial paragraph after the first third of the extracted text, with a bounded last-resort candidate. Such fallback prose need not be the true abstract. `extract_figure_captions` recognizes figure markers, gathers multiline bodies, bounds captions to a sentence/character budget and deduplicates figure numbers, while rejecting some TOC/cross-reference fragments. `extract_sections` recognizes numbered, `Part N` and fixed named headings and rejects TOC-like lines. Caption cleaning includes NFKC glyph folding; this is text normalization, not semantic or mathematical verification. `summarize_structure` normally scans the first 14 pages for abstract/sections (with a whole-text abstract fallback) and the whole document for captions. These are heuristics, not a guarantee of correct structure on every PDF. Earlier reports of a roughly 1200-character abstract and six sections from *Policy Entanglement in Active Inference* are historical observations, not a fresh extraction or corpus-wide accuracy result.

## Composing the Paper Demo

`paper/script.py`'s `build_paper_demo` assembles a title card, optional rendered title page, sentence-chunked abstract, optional structure scene, selected figures with matched captions or generic fallback narration, supplied PDF-page images, optional codebase architecture and an outro. It produces ordinary scene/chunk/action data; title/author metadata, section detection and figure-caption matching still require review against the source paper. Figure images use contain fitting before any explicit zoom, with the section and narration caption in separate bands ([@sec:composition]). [@fig:frame_paper] is a historical illustration of that initial composition, not proof of the current paper's publication status or a universal no-crop property.

![Historical paper-figure slide under the `paper` theme, showing an externally supplied coupling-potential graph labeled as from *Policy Entanglement*. Narration templates require no LLM; fixed extracted inputs and overrides determine the authored Demo. This does not imply that different extraction, synthesis or encoder environments yield identical voiced media. The ordinary pipeline supplies themes, scheduled actions, waveform and transitions. `verify_video` checks media properties and sampled content/energy, not caption faithfulness, intelligibility, scientific correctness or acoustic onsets ([@sec:evaluation]). The following is an illustrative two-step workflow, not an executed receipt; it requires the actual PDF, optional source/figure inputs and poppler, then ffmpeg/ffprobe and a usable voice for rendering. The image allow-root is explicit in the render command:

```bash
democreate paper ./inputs/paper.pdf --repo ./code --figures ./inputs/figures -o out/paper --no-render
democreate render out/paper/demos/paper.json -o out/paper --asset-root ./inputs --tts system --theme paper
```

The `paper` command can also render directly and currently derives its image root from `--figures` or the PDF's directory; it does not expose a separate `--asset-root` option. For an authored or generated Demo rendered separately, choose a root that permits the actual external image paths. The pipeline stages accepted images into the output workspace and emits workspace-relative resolved paths; that resolved artifact is distinct from the pre-render `paper.json`. Existing outputs, historical PNGs and the command text do not establish that these prerequisites have been exercised.

## Worked Example: *Policy Entanglement in Active Inference*

Historical documentation reported a template paper run from a 170-page *Policy Entanglement* PDF and associated codebase, producing 12 scenes and a 188.0-second video. This is not a current 0.8.0 receipt. The curated showcase is a distinct hand-authored artifact, with separately supplied external paper inputs; neither workflow substitutes an unrelated paper when inputs are absent.

The historical report describes 1920×1080 H.264 output and −15.5 dB mean volume. Mean dB is not integrated LUFS, not proof of the configured −16 LUFS target, and not proof of intelligible speech. A fresh output needs its own stream, energy, picture and identity evidence.
