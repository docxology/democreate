# Implementation {#sec:implementation}

DemoCreate is organized as a single `democreate` package under `src/`, with shared top-level modules and eight subsystem packages (`capture/`, `narration/`, `animation/`, `codebase/`, `assembly/`, `export/`, `paper/`, `translation/`). This section maps the implementation and distinguishes core defaults from optional adapters. The existing synthetic-editor and waveform illustrations ([@fig:frame_code; @fig:waveform]) are historical assets, reviewed 2026-11-07; their extraction dates are unrecorded, and they are not fresh candidate 0.8.0 render receipts.

## Module Map

The top-level modules hold the shared, dependency-light primitives that the subsystems exchange:

| Module | Responsibility |
|--------|----------------|
| `schema.py` | The declarative spine: `Demo`, `Scene`, `Chunk`, `Action`, `ActionType`, `SceneKind`, `WordTimestamp` ([@sec:architecture]) |
| `config.py` | `Theme`, `AudioConfig`, `VideoConfig`, `RenderConfig`, and the `THEMES` presets ([@sec:composition]) |
| `media.py` | Shared value types: `AudioClip` (a rendered narration file and its measured properties) and `FrameState` (a renderable snapshot of the virtual environment) |
| `pipeline.py` | The `Pipeline` orchestrator, `PipelineResult`, `build_demo`, and `render_video` |
| `cli.py` | The `democreate` command-line interface (Typer [@typer2024] + Rich [@rich2024]) |
| `project_paths.py` | The `Workspace` path resolver that creates and exposes all output sub-directories |
| `errors.py` | The exception hierarchy rooted at `DemoCreateError` (`SchemaValidationError`, `BackendUnavailableError`, `SyncError`, `RenderError`, …) |
| `_logging.py` | Self-contained structured logging and the `log_stage` context manager |

## `capture/` — The Visual Track

The capture subsystem produces the visual surface of each scene. Its centerpiece is the **synthetic renderer**, exposed by `capture/screen.py` and implemented in `capture/_screen_renderer.py`: the default `SyntheticRenderer` turns a `FrameState` into a Pillow image by drawing an editor, terminal, browser, or slide — a virtual desktop in the CodeVideo lineage [@codevideo2024]. It requires the core Pillow dependency [@pillow2024], not a live desktop or browser. Height-relative metrics and Pillow's bundled scalable font (`animation/fonts.py`) avoid host-font discovery; this is not a guarantee of identical pixels across different library builds. Pygments [@pygments2024], when available, supplies syntax tokens mapped to the theme palette; the fallback uses plain text coloring. Background images are initially fit by contain into the content area, with separate section, caption and waveform bands. Explicit camera scale and optional Ken Burns can crop that content ([@sec:composition]). [@fig:frame_code] illustrates a synthetic editor with a highlighted line, section label and caption.

![A synthetic `CODEBASE` editor frame rendered by `SyntheticRenderer`: scaled TrueType fonts, a line-number gutter, pygments syntax highlighting, an emphasized line, a section label pill, and a word-wrapped caption band — all drawn in pure Pillow with no real-pixel capture.](figures/frame_code.png){#fig:frame_code}

The optional `MssScreenCapture` backend uses the `capture` extra [@mss2024] to grab real screen pixels. `capture/terminal.py` models supplied command/output pairs as timed events serialized to asciinema asciicast v2 [@asciinema], without launching a shell, echoing the durable-capture approach of asciinema and termtosvg [@termtosvg]. Website frames are synthetic by default: a displayed URL is not evidence that a page was fetched or an interaction succeeded. `capture/browser.py` separately exposes a Playwright driver [@playwright2024] requiring the optional package and an installed browser binary; installing the extra does not automatically replace the pipeline's synthetic renderer. `capture/replay.py` provides an event model with optional real backends over pynput [@pynput2024] and pyautogui [@pyautogui2024].

## `narration/` — The Audio Track

The narration subsystem owns script generation, synthesis and duration-based synchronization. The default `auto`/`silent` backend writes silent WAV files; it is not spoken narration. System and Kokoro TTS are implemented optional voice paths; Chatterbox and Whisper remain unwired slots. The default `HeuristicTranscriber` interpolates known text by character length over a measured WAV duration. Neither those word estimates nor measured clip boundaries recognize speech or detect acoustic word onsets. Derived action timestamps marked `timestamp_source="sync"` are refreshed on synchronization, while authored absolute timestamps without trigger words are preserved. See [@sec:synchronization].

## `assembly/` — Timeline, Audio, and Animation

`assembly/compositor.py` builds non-overlapping narration windows that retain configured lead/inter-chunk silence; these windows are not a gap-free sequence of speech. A `TimelineEntry` contains a representative final still (`state`) and a scene-opening state plus absolute-time action stream. `state_at_ms` replays that stream at a requested time, so events are invisible before their triggers, code and pointer/camera changes interpolate over action durations, and supplied terminal output appears on command completion. The `ManifestCompositor` writes `render_manifest.json` and one representative PNG per entry. These stills do not by themselves demonstrate the animated schedule, and rendered commands are not executed.

`assembly/audio.py` post-processes the voiceover with pure-stdlib primitives plus guarded `ffmpeg` steps. `concat_with_gaps` concatenates the per-chunk WAVs in order, inserting lead, inter-chunk, and trail silences generated at the clips' own `(channels, sampwidth, framerate)` so nothing resamples; `measure_duration_ms` reads true durations from the WAV header. `normalize_audio` applies `ffmpeg`'s `loudnorm` filter — the EBU R128 [@ebu2020r128; @ffmpegloudnorm2024] integrated-loudness, true-peak, and loudness-range standard, defaulting to −16 LUFS — and `apply_fade` adds gentle in/out fades; both are guarded and raise `BackendUnavailableError` when `ffmpeg` is absent.

`assembly/animator.py` samples the timeline at `animation_fps`. In the pipeline path it calls `TimelineEntry.state_at_ms` for the current time and re-renders changing states, caching only the most recent state for each of at most two active chunks. Typing follows action timestamps and durations rather than revealing every chunk's final code across a fixed fraction of its audio window. Disabling typing reveals complete code at its trigger but leaves other action durations intact. The lower-level still/frame-state path retains the separate `typing_fraction` behavior. The animator can add scene crossfades, scheduled cursor motion and click ripples, waveform, progress and metadata overlays. Ken Burns is off by default; opting in can crop slide/background content. These are scheduled visual effects, not evidence of acoustic word/keystroke alignment.

`animation/waveform.py` reduces a 16-bit PCM WAV to normalized RMS amplitude buckets and draws mirrored played/unplayed bars. [@fig:waveform] illustrates that amplitude visualization at 55% progress; a silent default WAV contains no speech envelope. `animation/diagram.py` renders architecture diagrams (such as [@fig:architecture]); `assembly/captions.py` emits SRT, VTT and ASS subtitles, including a word-level path driven by `absolute_word_timestamps`. Under the default heuristic those word-level cues remain estimates, not STT observations. `assembly/effects.py` provides Pillow image effects.

## `animation/`, `codebase/`, `export/`, and `paper/`

`animation/zoom.py` and `animation/highlights.py` provide zoom/pan math and code emphasis. `animation/manim_scenes.py` builds data-only code-walkthrough specifications; its Manim render adapter [@manim2024] remains unwired even when the `animation` extra is installed. Such specifications are distinct from rendered systems such as code-video-generator [@codevideogenerator2023] and Code2Video [@code2video2025]; no comparative performance result is asserted here. `codebase/walker.py` extracts Python `ModuleSummary` values — docstrings, top-level functions, classes/methods, imports and line counts — using stdlib `ast`. Installing tree-sitter [@treesitter2024] does not make this default walker a demonstrated multi-language analyzer. `codebase/ast_viz.py` and `codebase/dependency.py` visualize summaries and import graphs. Repository-summary terminal commands and their supplied sample output are illustrative, never executed by the generator; discovered test-function counts are not passing-test receipts.

`export/formats.py` serializes the Demo and Markdown transcript. `export/interactive.py` uses Jinja2 to embed a caption/chapter timeline, CSS and JavaScript in an HTML player, but references the compositor's sibling `../frames` directory; it is not a single-file embedded-media bundle or the animated MP4. Distribute those files together. `export/video.py` encodes animated frames and assembled audio into H.264 MP4 using the ffmpeg binary. The optional `video` extra does not supply that executable, and the legacy MoviePy compositor remains unwired. `export/verify.py` checks stream geometry/duration, sampled image content and audio energy ([@sec:evaluation]); passing those checks does not establish intelligible speech, acoustic synchronization or authorship. Core-only builds provide silent WAVs, stills, captions, a transcript, resolved JSON and the HTML/frame bundle; voiced/encoded outputs need their real prerequisites and do not carry a universal cross-machine byte-identity guarantee. The `paper/` subsystem is described in [@sec:paper].
